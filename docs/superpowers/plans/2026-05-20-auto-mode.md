# Auto Mode (`--auto`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `--auto` flag to six long-running commands (`/feature`, `/fix`, `/ship`, `/ship-all`, `/implement`, `/design`) that skips ceremonial checkpoints and applies constitution-driven defaults while preserving user control at important decisions. All auto-decisions are visible inline, logged to `.agentic/auto-log.md`, and summarized at command end.

**Architecture:** Per-invocation flag (no persistent state). Each checkpoint in a command's instructions gets a tag (`[AUTO: skip]`, `[AUTO: ask-if-ambiguous]`, `[AUTO: always-ask]`). A hard-override list forces pauses regardless of tag (review blockers, destructive ops, missing project state). Auto-mode reads `CONSTITUTION.md` (especially a `## Default Decisions` section, scaffolded by `/init`) as the source of truth for default choices. Composes with the focus pointer: under `--auto`, `set_by:` gets an `(auto)` suffix and `/focus done` auto-promotes NEXT silently.

**Tech Stack:** Markdown skill files only. No code, no installer changes.

The focus plan's Task 3 already has the auto-promote logic and Task 13 already passes `auto` into `/focus done`; this plan tags the existing checkpoints in the auto-supporting commands.

**Files:**

- [ ] **Step 1: Insert a new section after "Caveman Communication Rules"**

Edit `agentic-engineering/skills/agentic-engineering/SKILL.md`. Find the "## Caveman Communication Rules" section (around line 63). Insert a new section between it and "## Context Management":

````markdown
## Auto Mode (`--auto`)

Long-running commands accept `--auto`: `/feature`, `/fix`, `/ship`, `/ship-all`, `/implement`, `/design`. The flag is per-invocation only — no persistent toggle, no project default.

Under `--auto`, every checkpoint in the command file is consulted by its tag:

| Tag | Behavior under `--auto` |
|---|---|
| `[AUTO: skip]` | Always skipped. For pure ceremony ("Reply 'go' to start"). |
| `[AUTO: ask-if-ambiguous]` | Skip if the answer is obvious from CONSTITUTION.md or context. Ask otherwise. |
| `[AUTO: always-ask]` | Never skipped. For architectural / destructive / unrecoverable choices. |
| (untagged) | Defaults to `always-ask` (safe failure). |

### Hard-Override List

Regardless of tag, auto mode pauses and asks when **any** of these are true:

1. `/review` reports a blocker — high-severity bug, requirements miss, or constitution violation.
2. Operation touches: CI configs (`.github/workflows/*`, `.gitlab-ci.yml`, etc.), secrets (`.env*`, `*secret*`, `*credential*`, `*.pem`, `*.key`), force-push, DB migrations creating/dropping tables, mass file deletion (>10 files).
3. `CONSTITUTION.md` explicitly contradicts the recommended action.
4. Required project state is missing — no test framework, no design tool chosen, no feature directory.

### Ambiguity Heuristic (for `[AUTO: ask-if-ambiguous]`)

- Multiple viable options, no constitution directive → ambiguous → ask.
- One option matches a constitution directive → not ambiguous → proceed + cite.
- Single viable option only → not ambiguous → proceed.
- Decision has cascading effects (>3 files, public-interface change, data-model change, new dependency) → treat as ambiguous regardless.

### Visibility

Every auto-decision is announced inline + appended to `.agentic/auto-log.md` (gitignored, alongside `.agentic/focus.md`):

```
DECISION: <choice>
  reason: <why, citing CONSTITUTION.md when applicable>
  [auto]
```

`SKIPPED:` for ceremonial skips. `HARD-PAUSE:` for forced pauses. Command ends with a one-line summary: `🤖 Auto mode: N decisions, M hard-pauses. See .agentic/auto-log.md`.

### Composition with /focus

When CURRENT is written by an `--auto` command, `set_by:` gets an `(auto)` suffix. `/focus done` under auto mode auto-promotes NEXT item #1 silently (no y/n/b prompt).
````
