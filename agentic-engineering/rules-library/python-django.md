# Python + Django Rules

## Apps and models
- One concern per app — `users`, `orders`, `payments` separate apps
- App has: `models.py`, `views.py`, `serializers.py`, `urls.py`, `admin.py`, `apps.py`, `tests/`
- Models use explicit field types — don't rely on auto-generated primary keys without thought
- `Meta.ordering` set on models where order matters
- `__str__` defined on all models — improves admin and debugging

## QuerySets
- Always use `select_related()` for FK, `prefetch_related()` for M2M — prevents N+1
- Custom managers for reusable queries: `Order.objects.pending()` not `Order.objects.filter(status='pending')` scattered
- Never evaluate QuerySets in loops — evaluate once, iterate
- Use `.only()` / `.defer()` for large tables when only some fields needed

## Views
- Class-based views for CRUD — `ListView`, `DetailView`, `CreateView`, `UpdateView`
- Function-based views OK for simple cases or unusual logic
- DRF `ViewSet` for APIs — not individual APIView classes unless necessary
- Permission classes explicit on every view — never rely on defaults
- Never put business logic in views — services or model methods

## Serializers (DRF)
- Separate serializers for list vs detail (detail has more fields)
- `read_only_fields` for fields users shouldn't set (id, created_at, user when derived from request)
- Validate in `validate_<field>` and `validate` methods — not in views
- Source: ORM field — never expose raw model to serializer if it has sensitive data

## Migrations
- One migration per logical change — don't squash commits into one migration
- Data migrations separate from schema migrations
- Review autogenerated migrations — rename them to be descriptive
- Never edit a migration that's been deployed to any environment

## Settings
- Settings split by environment: `base.py`, `dev.py`, `prod.py`
- Secrets via environment variables — `django-environ` or similar
- `DEBUG = False` enforced in production via config check
- `ALLOWED_HOSTS` set explicitly — never `['*']` in production

## Security
- CSRF middleware on — never disabled without written justification
- SQL via ORM — raw SQL only with parameterized queries
- User input never trusted — validate in forms/serializers, not just frontend
