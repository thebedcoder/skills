## File 2: Transcript

**Filename:** `premortem-transcript-[target-slug]-[YYYY-MM-DD].md`

Full reasoning trail — context capture, raw premortem (numbered list), each investigator's full output, full synthesis. No summarizing, no pruning. This is the audit trail you'd want if you came back in 3 months and wondered "what did we think was going to kill this?"

## File 3 (optional): HTML report

**Emit only if `$ARGUMENTS` contains `--html`.**

**Filename:** `premortem-[target-slug]-[YYYY-MM-DD].html`

Single self-contained file. Inline CSS. No external assets, no JS, no fonts loaded from CDNs — must work offline and survive being emailed.

### Design spec

- **Theme:** dark background (`#0a0e1a` body, `#141927` cards), high-contrast typography. System font stack only — `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`.
- **Layout:** single column, max-width 880px, centered. Mobile-readable (no horizontal scroll at 375px).
- **Header:** target name (large), date, captured-context line in muted text.
- **Synthesis block (top, prominent):** four sub-sections — Most Likely Failure, Most Dangerous Failure, Hidden Assumption, Revised Plan, Pre-Launch Checklist. Each in a colored bordered card. Most Likely uses amber accent (`#f59e0b`); Most Dangerous uses red (`#ef4444`); Hidden Assumption uses violet (`#a78bfa`); Revised Plan + Checklist use a calm green (`#10b981`).
- **Failure cards (below synthesis):** grid of cards, one per investigator output. Each card:
  - Numbered header with the failure reason
  - Three labeled sections: Story, Underlying Assumption, Early Warning Signs
  - Distinct accent color per card (rotate through a 6-color palette so they're visually scannable)
- **Footer:** small-print timestamp, target slug, "Generated by premortem skill"

### Style discipline

- No emoji except section markers (🔮 in the title is fine, nothing else)
- No animations, no hover effects beyond a subtle border lift
- No gradients on text (kills accessibility)
- Type scale: body 16px, h1 32px, h2 22px, h3 18px, small 13px
- Line-height 1.6 on body text

### Skeleton

```html
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>Premortem — [Target]</title>
<style>
  /* inline CSS — see design spec above */
</style>
</head>
<body>
  <main>
    <header>
      <h1>🔮 Premortem — [Target]</h1>
      <p class="meta">[YYYY-MM-DD] · [audience] · success: [...]</p>
    </header>

    <section class="synthesis">
      <article class="card likely">    <h2>Most Likely Failure</h2>     [...] </article>
      <article class="card dangerous"> <h2>Most Dangerous Failure</h2>  [...] </article>
      <article class="card assumption"><h2>Hidden Assumption</h2>       [...] </article>
      <article class="card revised">   <h2>Revised Plan</h2>            <ol>[...]</ol> </article>
      <article class="card checklist"> <h2>Pre-Launch Checklist</h2>    <ul>[...]</ul> </article>
    </section>

    <section class="cards">
      <article class="failure" data-accent="0">
        <h3>1. [Failure reason]</h3>
        <h4>Story</h4>          <p>[...]</p>
        <h4>Underlying Assumption</h4> <p>[...]</p>
        <h4>Early Warning Signs</h4>   <ul>[...]</ul>
      </article>
      <!-- repeat per failure -->
    </section>

    <footer>
      <small>[ISO timestamp] · premortem-[slug] · Generated by premortem skill</small>
    </footer>
  </main>

</html>
```

The HTML is a *presentation copy* of the markdown synthesis report — same content, different medium. Don't re-think the analysis when emitting it. If markdown and HTML disagree, markdown is canonical.
