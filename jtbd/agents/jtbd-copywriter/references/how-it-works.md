# How It Works Section Guide

## JTBD Mapping
Steps follow the customer's job — not the product's feature flow
Each step = one outcome unlocked (reduces Habit + Anxiety)

## Rules
- 3–5 steps maximum
- Each step: [Step name]: [action] → [outcome unlocked]
- The sequence should feel like progress toward the desired outcome
- Never write steps as a tutorial ("Click the button to...")
- The last step should land on the desired outcome from the focus job statement

## Step Format
```
Step N — [Name]: [What the customer does] → [What becomes possible]
```

## Test
Read the steps aloud. Does it sound like a story of the customer's progress? Or a product demo?
If it sounds like a demo → rewrite from the customer's perspective.

## Anti-patterns
- ❌ "Sign up and create an account" (assumed, not a step)
- ❌ Steps that describe UI ("Navigate to the dashboard")
- ❌ More than 5 steps (Anxiety increases with complexity)
